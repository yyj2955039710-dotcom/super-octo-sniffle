【边界澄清专项说明】

一、财务审计/会计审计与信息化项目审计的区分规则

【核心区分】
- 财务审计/会计审计：采购内容是"财务报表审计""年度审计报告""会计鉴证"等，审计对象是财务账目、资金流向、报表科目等财务数据，审计依据是会计准则、财务制度
- 信息化项目审计：采购内容是"信息系统审计""信息化项目审计""结算审计"等，审计对象是信息化项目建设内容、工程量、合同金额、软件造价等

【判断要点】
1. 看正文是否明确写明"财务报表""会计账簿""资金流向""年度审计"
2. 看审计依据是否为会计准则、财务制度
3. 看审计成果是否为"财务审计报告""会计鉴证报告"
4. 看审计对象是否为信息化项目建设成果、软件成本、信息化项目经费

【属于"否"的典型场景】（财务审计）
- "委托会计师事务所开展年度财务报表审计"
- "对局机关年度经费使用情况进行财务审计"
- "行政事业单位内部控制审计"

【属于"是"的典型场景】（信息化项目审计）
- "对政务平台软件开发费进行结算审计"
- "信息化项目建设资金使用情况审计"
- "信息系统工程造价审计"

二、结算审计与工程造价咨询的区分规则

【核心区分】
- 结算审计：针对已完成的信息化项目建设成果，审核工程量、合同金额、软件造价等，出具结算审核报告
- 工程造价咨询：针对建设工程的预算、招标控制价、结算进行造价审核，包括清单编制、预算审核、结算审核等，范围更广

【判断要点】
1. 看审计对象是否为信息化项目（软件系统、平台、数据资产等）
2. 看正文是否出现"工程造价咨询""造价审核""工程结算"等混用表述
3. 若正文同时出现"信息化项目"和"结算审计"，优先按信息化项目审计判断
4. 若正文出现"建设工程""土建工程""装饰工程"等，判"否"

【属于"否"的典型场景】（工程造价咨询）
- "某房建项目结算审计服务采购"
- "某市政道路工程造价咨询服务"
- "某工程项目工程量清单编制服务"

【属于"是"的典型场景】（信息化项目结算审计）
- "对智慧城市平台软件开发费进行结算审计"
- "某政务系统信息化建设项目结算审核"
- "数据安全态势感知平台项目结算审核服务"

三、IPO/证券监管场景特殊规则

【背景说明】
当项目涉及IPO上市、证券监管合规、上市公司信息披露等场景时，即使采购内容为信息系统/信息化项目审计，也可能要求审计报告由具有证券从业资格的会计师事务所出具。

【判断要点】
1. 看正文是否明确出现"IPO""上市""证券""上市公司""证监会""银保监"等关键词
2. 看审计报告用途是否为"满足监管要求""符合信息披露规定"
3. 看资质要求是否为"具备证券从业资格的会计师事务所"

【处理规则】
- 若项目业务属性属于信息化项目审计，但存在IPO/证券监管场景，应在"风险提示"中注明"可能对报告出具主体有监管要求，建议核实是否需会计师事务所联合出具"
- 若正文明确要求"具备会计师事务所执业许可证"，按资质强排除项处理

四、审计人力外包与第三方审计服务的区分规则

【核心区分】
- 审计人力外包采购：采购内容是"审计人员""审计工程师""驻场人员"等，人力被采购方以劳务/派遣/外包形式派遣至采购方，采购的是"人力资源"
- 第三方审计服务采购：采购内容是"审计服务""审计机构""第三方审计"等，由审计机构以独立机构身份承接审计项目，对审计过程和结果负责，采购的是"审计服务成果"

【判断要点】
1. 看采购标的表述是"采购X名审计人员"还是"采购X审计服务"
2. 看交付成果描述的是"人/人力"还是"审计报告/整改建议书"
3. 看工作模式是否为"派遣至采购方工作""受采购方管理"

五、重复数据处理规则

【重复数据定义】
1. 同一采购项目的不同公告阶段重复（如：招标公告+更正公告+中标公告为同一项目）
2. 同一项目名称、不同采购批次的重复
3. 同一项目、不同信息源的重复
4. 标题和正文内容高度相似且核心信息一致的重复

【处理原则】
1. 若判断为重复数据，只保留信息最完整、时效最新的公告版本
2. 其他重复版本标注"重复数据，不计入商机列表"
3. 若重复数据中某一版本包含关键新增信息（如预算金额变化、采购范围调整），则保留该版本

【输出处理】
对于重复数据，需在输出中体现"是否为重复数据"和"重复数据说明"字段。

【最高优先级裁决总则】
1. 本任务判断对象仅限于"第三方独立审计机构可承接的信息系统/信息化项目/数据类审计服务采购机会"。
2. 必须以正文中明确披露的采购内容、服务范围、成果要求、实施方式、实施对象、资质要求为核心依据。
3. 标题、项目背景、建设目标、验收目标、上线目标、合规安排等，仅可作为辅助线索，不得替代正文采购内容。
4. 若正文明确采购内容不是第三方审计服务，即使标题或背景中出现"审计""专项审计""结算审计""绩效审计"等字样，也应优先判定为"否"。

7. 若文本存在审计迹象，但无法确认采购对象是否为第三方独立审计服务本身，应判定为"不确定"。
8. "是否属于商机"优先判断业务属性是否属于第三方信息化/信息系统/数据类审计服务采购机会；"推荐跟进""跟进优先级""风险提示"可结合资质适配性综合判断。
9. 若正文明确要求投标人/供应商必须具备我司当前不具备且不可替代的特定资质，则即使该项目业务属性属于第三方审计服务，仍不得改变其业务属性判断；但应在输出中体现为"不建议跟进"、低优先级，并在判断依据或风险提示中明确说明为资质不匹配。

【判断思路】
按以下顺序进行判断：
1. 先识别正文核心采购对象：审计服务 / 开发建设 / 运维服务 / 咨询 / 检验检测 / 监理配合 / 其他。
2. 再判断是否明确采购"第三方独立审计机构"开展审计服务。
3. 再看是否有清晰的审计类型、审计对象、实施方式、交付成果。
4. 再判断资质要求是否构成实质性准入门槛，以及是否属于我司可匹配资质。
5. 若标题疑似审计项目，但正文明确主采购内容不是审计服务，以正文为准。
6. 若正文明确为建设、开发、集成、运维、咨询、检测认证等其他服务，即使与审计相关，也优先判"否"。
7. 若存在一定审计迹象但关键信息不足，判定为"不确定"。

【资质适配规则】
一、资质强排除项
若正文明确将以下任一资质列为投标人/供应商/服务机构必备资格条件，且语义明确为"须具备""必须具有""资格条件要求""未提供不得参与""作为实质性资格条件"等，则视为我司资质不匹配信号：

- 国家审计署认定的特定审计资质
- 具备金融监管审计资质（如银保监、证监会指定机构资质）
- 我司当前已有资质：数据安全服务能力评定资格证书（一级）、CNAS、CMA、ITSS、CMMI3、团队含CPA/CISA/CIA人员；申请中：信息系统审计机构服务能力三级资质（中国计算机用户协会）。若正文要求供应商机构本身须取得会计师事务所执业许可证/注册会计师事务所执业资质，视为我司不匹配；若仅要求团队人员中具备注册会计师证书，我司可满足，不触发排除。若项目背景为IPO上市、证券监管合规等场景，即使采购内容为信息系统审计，仍需在风险提示中注明"可能对报告出具主体有监管要求，建议核实是否需会计师事务所联合出具"。
 处理规则：
1. 若项目业务属性本身属于第三方审计服务商机，仍应保持"是否属于商机"为"是"；但"推荐跟进"应优先判为"不建议跟进"，"跟进优先级"优先判为"低"，并在"判断依据"或"风险提示"中明确说明存在我司不具备的资质门槛。
2. 若项目正文同时显示其核心采购内容本就属于财务审计、会计审计、税务鉴证等非本任务范围，则优先按业务属性判"否"。
3. 若仅出现上述资质名称，但无法确认是否为投标资格条件，不得直接按资质不匹配排除，优先判为"可观察"或进入人工复核池。
 
二、资质命中项
以下资质仅在已确认项目属于信息化/信息系统/数据类第三方审计服务前提下，方可作为正向匹配信号：
- 信息系统审计机构服务能力资质（中国计算机用户协会）
- 数据安全服务能力评定资格证书
- CNAS / CMA 检验检测机构资质
- ITSS 信息技术服务标准符合性证书
- CMMI3 及以上成熟度证书
 
处理规则：
1. 信息系统审计机构服务能力资质仅在项目明确属于信息系统/信息化项目类审计服务时，可作为正向匹配信号；若项目本质为财务审计或会计鉴证，仍按非本任务范围处理。
2. CNAS/CMA 仅在项目明确属于信息系统审计、数据安全审计等信息化审计服务时，可视为正向适配；若项目属于设备、材料、环境、工程等检验检测业务，不得据此判定为本任务商机。
3. 命中项资质不能单独支撑"是否属于商机"为"是"，只能作为已属于目标业务前提下的辅助判断依据。
 
三、资质歧义规则
- 若正文写"优先具备""建议具备""具备者优先"，通常不视为强制排除条件。
- 若资质要求大量依赖附件、资格审查表、评分表，而当前输入未展示，不得直接据此做强排除，应视情况进入人工复核池。
- 若标题或正文含"审计机构""评估机构"等表述，需区分是信息系统审计服务机构，还是财务审计/会计师事务所/检测评估机构，不得混淆。
 
【高混淆场景特别规则】
1. "配合审计"不等于采购第三方审计服务。
2. "专项审计"必须区分实施主体：
   - 若明确采购第三方机构开展专项审计，可判"是"；
   - 若为主管单位组织审计、中标方配合审计，通常判"否"。
3. "数据安全审计"要与"数据安全评估/等保测评"区分：
   - 第三方数据安全审计服务可判"是"；
   - 网络安全评估、等保测评通常判"否"。
4. "审计系统""审计平台""审计工具"不等于审计服务。
5. "联调联试""试运行""调试"通常不是第三方审计商机。
6. "信息化项目+审计打包项目"只有在正文明确单列采购第三方审计服务时，才能判"是"；否则优先判"否"。
7. "检验检测"与"信息系统/信息化项目第三方审计"不是同一类业务，默认不纳入本任务范围。
8. 出现 CNAS、CMA、信息系统审计资质时，必须先确认项目对象是信息系统、信息化项目、数据资产等审计服务，而非传统检验检测或财务审计。
9. 出现财务审计、内部审计相关资质要求时，要同时判断该项目是否实质属于财务鉴证、会计审计类项目；若是，优先判"否"。
 
【不同公告类型专项规则】
1. 招标/采购公告类：以采购内容、服务范围、成果要求、资质要求、实施对象为核心判断。
2. 中标/成交结果公告类：
   - 若项目名称或正文明确写明第三方审计服务、信息系统审计、结算审计等，可判"是"，置信度视信息完备度为中或高；
   - 若仅项目名称出现"审计"字样，正文无采购内容支撑，优先判"不确定"。
3. 合同公告类：
   - 若合同标的明确为第三方审计服务，可判"是"；
   - 若仅显示项目名称，未展示合同服务内容，优先判"不确定"。
4. 终止/流标公告类：
   - 若原采购内容明确为第三方审计服务，仍可判"是"；
   - 风险提示中注明"项目终止/流标，需关注后续重启机会"。
 
【最终裁决矩阵】
一、判定为"是"
满足以下之一：
1. 正文明确采购/委托第三方开展信息系统/信息化项目/数据类审计服务；
2. 正文明确采购审计机构实施管理控制、应用控制、数据控制、网络控制、安全控制、绩效、结算等审计；
3. 正文明确要求出具审计报告、专项审计报告、结算审核报告、整改建议书；
4. 正文明确为审计服务框架协议、审计机构库、审计入围、备选单位征集。
 
二、判定为"否"
满足以下之一：
1. 正文明确采购内容为开发、建设、集成、运维、咨询、培训、监理、检验检测等非第三方审计服务；
2. 正文仅体现满足审计要求、配合审计、支持专项检查、提供整改配合等配合性或过程性描述；
3. 标题疑似审计项目，但正文明确主采购内容不是第三方审计服务；
4. 采购对象为建设单位、实施单位、中标方自身配套工作，而非第三方独立审计机构；
5. 正文明确核心业务为等保测评、网络安全评估、财务审计、会计鉴证、商用密码应用安全性评估等非本任务范围业务。
 
三、判定为"不确定"
满足以下之一：
1. 标题或正文存在审计线索，但正文未明确采购范围；
2. 正文信息极少或关键内容缺失；
3. 仅见项目名称、金额、地点、中标人等基础信息；
4. 公告提示详见附件，但当前输入未展示审计服务内容；
5. 文本可能涉及第三方审计，但无法确认是否单独采购第三方独立审计机构；
6. 资质要求可能影响可参与性，但当前无法确认其是否为强制门槛。
 
【业务适配与跟进建议】
1. 业务属性判断优先于销售建议判断。无论是否建议跟进、门槛高低、是否结果公告，都不得反向改变"是否属于商机"的事实判断。
2. 推荐跟进：
   - 建议跟进：明确属于第三方审计服务，且处于招标/采购/拟采购/流标重启阶段，或结果公告仍具备后续框架入围机会，且未发现明显资质不匹配门槛。
   - 可观察：属于该类业务，但已中标/已签约/信息不完整/机会窗口较小/资质条件未明确。若项目投标/响应截止时间已过，"建议跟进"统一降为"可观察"，并在风险提示中注明"已过截止时间，建议关注后续同类采购或框架协议续签机会"。
   - 不建议跟进：明确不属于该类业务，或虽属于该类业务但存在我司当前不具备的明确强制资质门槛，或无实际跟进空间。
   - 明确"推荐跟进"只有三档，严格输出
3. 跟进优先级：
   - 高：采购内容明确、预算/范围清晰、可直接参与、无明显资质障碍。
   - 中：属于目标业务，但信息略缺、竞争较强、阶段稍晚，或需进一步核实部分资质要求。
   - 低：信息不足、窗口较小、结果类公告、资质明确不匹配或需长期观察。
   - 明确跟进优先级只有三档，严格输出
 
【置信度规则】
- 高：正文存在一级正向证据，且采购范围/服务对象/成果要求清楚；或正文存在明确一级反向排除证据。
- 中：正文较明确支持结论，但信息不完整；或结果公告仅凭项目名称+少量文字可判断；或业务属性明确但资质门槛判断仍需结合上下文。
- 低：证据依赖弱线索；正文过短；标题正文冲突；关键采购内容缺失；资质信息不清。
 
【人工复核池规则】
以下情形应进入人工复核池：
- 标题与正文冲突
- 仅项目名称含"审计""专项审计"，正文未展示采购内容
- 同时出现"建设/实施/监理"和"审计"但未明确审计是否第三方独立采购
- 结算审计、绩效审计、数据安全审计等存在主体歧义
- 公告正文大量依赖附件，当前输入未展示关键内容
- 结果公告/合同公告信息过少但存在审计迹象
- 资质要求可能构成门槛，但当前无法确认是否为强制资格条件
- 同时出现 CNAS/CMA/信息系统审计资质与"检测""鉴证"等表述，难以确认是否属于信息化审计而非传统检验检测或财务审计
- 出现财务审计、内部审计相关资质，但项目业务属性边界不清
 
【关键词提取规则】
关键词应优先提取最能支撑判断的业务词，不超过5个，避免泛词堆砌。优先级如下：
1. 审计服务名称：如"第三方审计""信息系统审计服务""结算审计"

5. 核心排除词：如"财务审计""等保测评""系统开发"
